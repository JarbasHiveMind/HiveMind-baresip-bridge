# AGENTS.md — `HiveMind-baresip-bridge`

Guidance for AI coding agents (and humans) working in this repository. Read it
fully before making changes. It encodes conventions that are not obvious from the
code and that, if ignored, produce work that will be rejected.

## Repo

A SIP-to-HiveMind bridge: it answers phone calls with
[baresipy](https://github.com/TigreGotico/baresipy) (the upstream SIP
library), runs the caller's audio through a local OVOS mic/VAD/STT loop, and
relays recognized speech to hivemind-core over the HiveMind bus, playing
hivemind-core's synthesized replies back into the call. Part of the
[HiveMind](https://github.com/JarbasHiveMind) ecosystem — a protocol for
connecting satellite devices to a hub running
[OpenVoiceOS](https://github.com/OpenVoiceOS). The hub is
[HiveMind-core](https://github.com/JarbasHiveMind/HiveMind-core); the client
library is
[hivemind-bus-client](https://github.com/JarbasHiveMind/hivemind-bus-client).
It works like
[HiveMind-voice-relay](https://github.com/JarbasHiveMind/HiveMind-voice-relay)
except the microphone is a phone call — the TTS retrieval mechanism
(`speak:b64_audio` / `speak:b64_audio.response`) mirrors voice-relay exactly
and any change to that flow here should stay consistent with it.

## Layout / build / test

- Package module: `hivemind_baresip_bridge/`. Tests live in `test/` (check
  before adding — do not create a second test directory).
- Set up a throwaway environment inside your clone; never touch a shared venv:
  `python3 -m venv .venv && VIRTUAL_ENV=$PWD/.venv uv pip install -e ".[test]" --prerelease=allow`
- Run the suite in the foreground: `python3 -m pytest test/ -q`. It mocks
  `HiveMessageBusClient` and baresipy's `pexpect.spawn`, so it runs without a
  live hub or a real `baresip` binary — treat it as a wiring/shape check, not
  proof that a real call, a real SIP registrar, or a real hivemind-core
  handshake works.
- `uv`, never `pip`. If latest prereleases fail to install or resolve, that is
  a bug to FIX at the source, not to work around with a pin downgrade.

## Tests

- Adversarial by default. A regression test must **fail before the fix and pass
  after** — prove it by reverting only the source (`git apply -R`, never
  `git stash` across worktrees) and watching the test flip.
- Tests must be mutation-proof: gutting the feature must fail the test. A test
  that only asserts a mock was called, without asserting the real behaviour, is
  weak — note it.
- Never skip a test because an optional dependency is missing.
- CI green is permission to review, not to merge. A non-trivial change gets an
  adversarial review before it lands.

## Repo-specific rules

- **Composition for the bus client, inheritance for the SIP client.**
  `__main__.connect()` builds one `HiveMessageBusClient`, calls
  `bus.connect(site_id=siteid)` on it exactly once, and only then constructs
  `BaresipBridge(sip_config=..., bus=bus, ...)`. `BaresipBridge` receives that
  already-connected client by injection and never calls `.connect()` or
  `.run_forever()` on it itself — that stays true even though `BaresipBridge`
  separately *inherits* from `baresipy.BareSIP` for the SIP side. Do not
  collapse these two relationships or add a second `connect()`/`run_forever()`
  call anywhere in the bridge.
- **Bound `handshake_max_retries`.** The current `bus.connect(site_id=siteid)`
  call in `__main__.connect()` does not pass `handshake_max_retries`, so it
  inherits `hivemind-bus-client`'s own default of `None` — retry forever. This
  is a standing defect, not a documented trade-off: against a stalled or
  unreachable hub the bridge hangs indefinitely instead of failing fast. Any
  change touching this call must add an explicit, finite
  `handshake_max_retries` (ideally exposed as a CLI flag, mirroring the
  pattern in sibling bridges), and the floor on `hivemind-bus-client` must be
  raised to `>=1.0.13a1` or later, which is where a bounded default landed.
- **Rejected credentials must fail fast.** The same bounded-retries fix is
  what turns "wrong access key/password" into a clean failure instead of a
  bridge that looks connected while silently retrying forever. Do not layer
  retry/backoff logic on top of `connect()` that defeats the bound once it
  exists.
- **ACL enforcement is the hub's job, not this bridge's.** A freshly
  registered HiveMind client is denied every message type until an admin runs
  `hivemind-core allow-msg recognizer_loop:utterance <client_id>` (and
  `speak`/`speak:b64_audio` as needed). This bridge cannot grant itself
  permissions and must not add local workarounds for a hub-side denial — a
  dropped message on the hub side is the hub doing its job. `SIPConfig`'s
  caller allowlist (`sip_config.is_allowed(number)`) is a separate, SIP-layer
  filter over which phone numbers may originate a call; it has nothing to do
  with hub-side bus-message ACLs.
- **Forward upstream responses verbatim.** `handle_tts_b64_response()` decodes
  and plays exactly the audio hivemind-core sent in
  `speak:b64_audio.response`; do not re-encode, resample, or otherwise alter
  hub-authored audio in this path.
- **No thread/async-loop bridging here — but treat call-state as
  concurrently accessed.** Unlike bridges built on an asyncio chat-platform
  SDK, this bridge has no event loop to hop across; bus callbacks
  (`handle_tts_b64_response`) and baresipy's own callback thread
  (`handle_incoming_call`, `handle_call_established`, `handle_call_ended`)
  can still run concurrently. `self._lock` guards `_listener`, `_caller`, and
  `_session_id` in `handle_call_established`/`_stop_listener`; any new code
  that reads or writes those fields from a callback must take the same lock
  rather than assuming single-threaded access.
